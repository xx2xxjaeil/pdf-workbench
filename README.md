# PDF Workbench

PDF Workbench는 기존 PDF나 빈 A4 페이지에 텍스트·표·이미지를 배치하고, 수정한 결과를 새 PDF로 내보내는 브라우저 기반 편집기입니다. 편집 내용을 프로젝트 파일로 저장해 나중에 다시 수정할 수도 있습니다. 파일은 별도 서버로 보내지 않고 브라우저에서 처리합니다. 현재 버전은 원본 PDF의 글자를 직접 바꾸는 대신, 원본을 보존하면서 새 요소를 추가하고 편집합니다.

## AI와 함께 만든 과정

이 프로젝트의 첫 버전은 **OpenAI Codex 데스크톱 앱을 주된 개발 도구로 사용**해 만들었습니다. 구현 코드와 테스트·문서의 상당 부분을 Codex가 작성·수정했습니다. 저는 주제를 선택하고 기능 범위와 우선순위를 정했으며, 동작을 확인하면서 더블클릭 편집·크기 조절 같은 후속 요구사항을 제시했습니다. AI의 제안을 그대로 제품 기능으로 소개하지 않도록, 구현한 것과 아직 구현하지 않은 것도 구분해 기록했습니다.

### 사용한 AI 작업 환경

- **AI 도구:** OpenAI Codex 데스크톱 앱. 설계 논의, 코드·테스트·문서 작성, 실행과 검토에 사용했습니다. 특정 실행 모델명은 확인 가능한 기록이 없어 기재하지 않았습니다.
- **저장소 지침:** 현재 [`AGENTS.md`](AGENTS.md)는 Next.js 개발 서버가 생성한 버전별 문서 확인 안내입니다. 프로젝트 전용으로 설계한 에이전트 작업 규칙은 아직 없습니다.
- **작업별 가이드:** Codex 환경에서 Next.js, PDF 처리, React 품질 점검 스킬을 참고했습니다. 이 스킬은 이 저장소에 직접 만든 파일이 아닙니다.
- **하네스와 하위 에이전트:** Codex가 제공한 실행 환경을 사용했으며 별도의 커스텀 하네스나 하위 에이전트는 구축·실행하지 않았습니다. 실제로 도입하면 역할과 결과를 기록할 예정입니다.

AI는 **개발 과정**에 사용했습니다. 현재 PDF Workbench 앱 자체에는 AI 기능이나 AI API 호출이 없으며, 실행에 AI API 키도 필요하지 않습니다.

## 현재 가능한 작업

- PDF 가져오기 및 페이지 이동. 25MB 이하, 회전·잘림이 없는 PDF를 지원합니다.
- 텍스트 추가·이동·수정, 글자 크기·굵게·기울임·색상·정렬 설정. 페이지의 텍스트를 더블클릭하면 바로 수정하고, 선택 테두리의 가장자리·모서리를 드래그하면 크기를 조절할 수 있습니다. 수정은 바깥을 클릭하면 저장되고 `Esc`로 취소됩니다.
- 표 추가, 행·열 증감, 셀 내용·글자 크기·색상·테두리 색상 설정.
- 5MB 이하 PNG/JPG 이미지 추가, 크기와 위치 변경.
- 실행 취소·다시 실행, 확대·축소, 새 PDF로 내보내기.
- `.pdfw` 편집 프로젝트 저장·열기. 원본 PDF와 추가한 요소를 함께 보관해 브라우저를 닫은 뒤에도 계속 편집할 수 있습니다.
- 한국어 글꼴을 PDF 안에 포함하고, 저장 결과를 다시 열어 페이지 수를 검증합니다.

### 편집 프로젝트와 PDF의 차이

`프로젝트 저장`은 원본 PDF와 추가한 요소를 포함하는 `.pdfw` 파일을 다운로드합니다. 나중에 `프로젝트 열기`로 불러오면 요소를 다시 선택·수정할 수 있습니다. 반면 `PDF 내보내기`는 다른 뷰어에서 읽을 수 있는 일반 PDF를 만듭니다. 내보낸 PDF를 다시 가져와도 개별 편집 요소로 복원되지는 않습니다.

프로젝트 파일은 버전 1 JSON 형식이며, 원본 PDF와 이미지를 포함하므로 원본보다 커질 수 있습니다. 최대 80MB까지 열고 저장합니다. **암호화되지 않으므로 민감한 문서가 들어 있다면 파일 공유에 주의하세요.** 실행 취소 이력은 프로젝트 파일에 저장하지 않습니다.

## 실행과 테스트

Node.js 20 이상과 npm이 필요합니다.

```bash
npm install
npm run dev
```

터미널에 표시된 로컬 주소로 접속하세요. `예제 열기` 버튼으로 2페이지 PDF 편집을 바로 체험할 수 있습니다.

```bash
npm run check   # Prettier, ESLint, TypeScript, 단위·PDF·프로젝트 파일 테스트 9개
npm run build   # 프로덕션 빌드
```

브라우저 E2E 테스트는 최초 한 번 Chromium을 설치한 뒤 별도로 실행합니다. 실행 중인 `localhost:3001` 개발 서버가 있으면 재사용하고, 없으면 테스트가 서버를 시작합니다.

```bash
npx playwright install chromium
npm run test:e2e
npm run test:e2e:ui # 테스트 과정을 화면에서 확인
```

Playwright E2E 테스트 4개는 기본 편집·내보내기, 원본 PDF 보존, `.pdfw` 저장 → 새로고침 → 복원 → 재편집, 손상된 프로젝트 파일 처리까지 검증합니다. 다운로드한 PDF는 다시 열어 페이지 수를 확인하고 PDF.js로 한글 편집 내용과 원본 텍스트를 추출해 검사합니다. 로컬에서 단위·PDF·프로젝트 파일 테스트 9개와 E2E 테스트 4개가 통과했습니다. [GitHub Actions](.github/workflows/ci.yml)는 push와 PR에서 검사·빌드·E2E를 실행하도록 설정했으며, 이번 변경의 원격 실행 결과는 push 후 확인해야 합니다. E2E가 실패하면 `test-results/`에 스크린샷과 실행 기록이 남습니다.

## 중요한 제한

기존 PDF의 글자나 그림 자체를 직접 수정하거나 삭제하지는 않습니다. 원본 페이지 위에 새 요소를 추가하는 방식이며, 겉으로 가려도 원본 내용이 삭제·가림 처리(redaction)되는 것은 아닙니다. 앱에서 새로 추가한 요소는 현재 편집 세션 또는 저장한 `.pdfw` 프로젝트에서 수정할 수 있지만, 내보낸 PDF를 다시 열면 일반 PDF 콘텐츠가 되어 개별 요소로 재편집할 수 없습니다.

현재 조판은 페이지 안에서 요소를 배치하는 수준입니다. 문단이 자동으로 여러 페이지에 이어지는 흐름 조판이나 원본 텍스트 교체는 아직 구현하지 않았습니다. 텍스트·표가 지정한 상자보다 길면 내보내기를 막고 크기를 늘리도록 안내합니다. 한국어 글꼴을 전체 임베딩하므로 출력 PDF 크기는 수 MB까지 늘어날 수 있습니다.

## 구조

`src/features/editor/model`은 요소 정의·변경 이력·프로젝트 파일 검증을, `src/features/editor/pdf`는 PDF 가져오기·렌더링·내보내기를, `src/features/editor/ui`는 화면을 담당합니다. 모든 요소의 좌표는 페이지 좌측 상단을 원점으로 하는 PDF 포인트 단위입니다. 자세한 설계와 확장 계획은 [architecture notes](docs/architecture.md)에 있습니다.
